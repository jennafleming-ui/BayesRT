# BayesRT - Formula 1 Race Strategy Optimization System

An integrated machine learning framework for real-time Formula 1 race strategy optimization, combining neural networks, weather prediction, risk assessment, and cognitive load monitoring.

## Overview

BayesRT is an AI-powered decision support system designed to optimize race strategy in Formula 1. The system analyzes real-time race data, weather conditions, and risk factors to recommend optimal pit stop timing, tire compound selection, and strategic decisions.

## Key Features

- **NeuroStrategy Engine**: Simulation-based multi-objective strategy optimization (forward-simulates pit strategies under tire-degradation curves; not a trained model)
- **WeatherWise**: Real-time weather prediction and circuit-specific forecasting
- **RiskCalc Pro**: Predictive risk assessment with confidence intervals
- **Cognitive Load Monitoring**: Driver performance and fatigue analysis
- **Real-time Dashboard**: Live visualization with WebSocket updates
- **Multi-objective Optimization**: Balances lap time, tire life, and track position

## Installation

### Prerequisites
- Python 3.9 or higher
- pip package manager

### Setup

1. Clone the repository:
```bash
git clone https://github.com/jennafleming-ui/BayesRT.git
cd BayesRT
```

2. Create a virtual environment:
```bash
python3 -m venv .venv
source .venv/bin/activate  # On Windows: .venv\Scripts\activate
```

3. Install dependencies (pinned versions):
```bash
pip install -r requirements.txt
```
> On Apple Silicon, if `tensorflow` fails to import, swap it for
> `tensorflow-macos` (see the note in `requirements.txt`).

## Usage

1. Start the server:
```bash
python3 dashboard_server.py
```

2. Open your browser and navigate to:
```
http://localhost:5001
```

3. The dashboard will display:
   - Current race state (lap, position, tire age)
   - Strategy recommendations
   - Weather forecasts
   - Risk assessments
   - Cognitive load metrics

## AI Components

### NeuroStrategy
- Simulation-based strategy optimization — forward-simulates candidate pit
  strategies under tire-degradation curves; a deterministic search, not a
  trained model (the name is historical, not a description of the method)
- Considers tire degradation, fuel consumption, and track position
- Ranks strategies by expected outcome; confidence currently reflects
  prediction horizon, not RiskCalc Pro's per-lap uncertainty — propagating
  that uncertainty into the ranking itself is the natural next step
- Generates multiple strategy alternatives

### WeatherWise
- Circuit-specific weather prediction
- Track temperature forecasting
- Rain probability analysis
- Integration with strategy recommendations

### RiskCalc Pro
- Predictive lap time modeling
- **Calibrated** uncertainty = epistemic (**MC-Dropout**, active at inference and
  sampled repeatedly) + aleatoric (irreducible residual noise, added in
  quadrature). On a temporal hold-out (same-race, the deployment scenario):
  **MAE 0.77–0.85s**, **~98% empirical coverage** of the nominal 95% interval
- **Cross-circuit generalization**, evaluated properly — leave-one-circuit-out
  cross-validation rotated across all 5 circuits, not a single random split:
  **MAE 2.49s ± 0.72s**, **74.2% ± 15.2% coverage**. Generalization difficulty
  is circuit-dependent (1.52s MAE holding out Australia vs. 3.39s holding out
  Monaco) — a single-circuit evaluation understates how hard this is, and
  which circuit you hold out matters as much as the average
- Benchmarked against a deep ensemble (5 independently-initialized members,
  which won on every proper-scoring-rule metric tested — MAE, CRPS, NLL — see
  `advanced_uq_analysis.py`) and split-conformal prediction (distribution-free,
  no Gaussian assumption). A formal PIT-Kolmogorov-Smirnov calibration test
  shows neither Bayesian method is truly calibrated across its full predictive
  distribution (p<0.0001) despite passing single-level coverage checks —
  reported here rather than only in the paper, since it's a real limitation
- Leakage-free: lap-time history is shifted so a lap never sees its own time
- Persisted feature schema + feature/target scalers so the saved model predicts
  reproducibly on a single new lap
- Real-time risk assessment

### CognitiveLoad Monitor
- Unsupervised, field-relative load **index** (0–100) — there is no ground-truth
  cognitive-load label in timing data, so the model estimates a latent construct
  from instability proxies (lap-time variability, degradation slope, spike rate)
  z-scored against the whole field
- Driver fatigue / performance-trend detection
- Alert thresholds for elevated and high load
